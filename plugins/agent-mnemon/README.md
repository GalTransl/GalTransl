# agent-mnemon · Python 全局/项目记忆精简版

基于 [dsh-mnemon](https://github.com/omdsh-dev/dsh-mnemon) **0.5.38**，参考提交
`a4ad2d6955172b936ff9328f39cc5873c3ec9c55` 的常驻记忆与按需检索思路，保留
上游 [MIT 许可](LICENSE)。Python 实现在 `GalTransl/Agent/mnemon.py`、
`mnemon_store.py` 和 `mnemon_prompts.py`。

## 开启与职责

**agent-mnemon** 默认开启，可在翻译或提取 Agent 左下角的齿轮配置窗口中关闭。
两个开关为 `mnemonEnabled`、`extractionMnemonEnabled`，独立控制，下一回合生效。
新安装和未保存开关的配置默认开启，已有明确关闭的设置继续保留。
翻译与提取的记忆独立，各自拥有全局和项目两层；工具和管理弹窗只访问当前类型 Agent 的记忆。

mnemon 保存跨会话需要复用的偏好与项目事实；billion-context 压缩、回查当前会话原文。
二者可以同时开启。核心使用 Python 标准库（包括 SQLite）和现有 Agent 审批流程，
不启动插件进程、不探测 Git 分支，也不需要额外运行依赖。

## 全局/项目两层、三种操作

| 工具 | 参数与行为 |
| --- | --- |
| `mnemon_recall` | `query` 必填；`limit` 默认 5，范围 1–5。同时搜索全局和当前项目，返回完整正文、id、scope、重要性与词法评分。 |
| `mnemon_remember` | `content` 必填，最多 1000 字符；新建的 `scope` 默认为 `project`，可选 `global`。提供 `id` 时更新原条目并自动定位范围；显式 scope 必须与原范围一致。`importance` 为 `normal` 或 `critical`，新建默认 normal，更新省略则保留原重要性。 |
| `mnemon_forget` | 按精确 `id` 删除明确撤回或过时的事实，自动定位范围。 |

全局层保存同类 Agent 的跨项目偏好、交流习惯和通用约定；项目层保存游戏、项目与环境的具体事实。
默认写入项目，只有需要跨项目复用的知识才使用 global。当前用户指令优先；项目专属约定
覆盖有冲突的全局默认约定。全局 id 以 `global-` 开头，项目 id 以 `mem-` 开头，
检索结果、常驻快照和写入回执都带范围，更新不会把条目移动到其他范围。

同一范围内空白归一化后相同的正文去重；重复保存返回原 id，显式指定重要性可调整原条目。
按 id 更新不能覆盖另一条相同正文的记忆，需明确删除多余条目。
更新保留 id 和创建时间，刷新更新时间。各范围的调用回执按项目/会话/工具调用 id 持久化，
重放不会再次修改数据；同 id 不同参数报错。读取直接放行，项目保存/更新和删除采用既有 high 审批规则。
全局新增、更新和删除在任何模式下都逐次审批，不接受本会话放行；只给全局 id 的变更也采用此规则。

`critical` 用于需要持续遵循的重要偏好和项目约定，按更新时间从新到旧自动加入请求快照；
`normal` 仅按需检索。快照合并两层，项目条目先于全局条目，各层内按更新时间排序；
保留完整条目、scope 与 id，两层共享最多约 1024 个估算 token，
同时受上下文窗口的 1/16 限制，预算包含固定指导语和快照头的预留。
超出预算的条目仍在同一个库中，不迁移、不删除，返回的 omitted 数提示常驻省略。
新会话首次运行时构建并保存快照，正文、指导语、排序与省略数量在整个会话内固定，
后续回合、停止重发、重新打开和进程重启均恢复同一份快照。
新增、更新和删除立即落库，检索和管理界面立即读取最新结果；仅新会话读取最新记忆进入 system。
开关仍控制当前回合的记忆工具，切换开关不会改写已有会话的 system 快照。
旧会话没有快照记录时不补读最新记忆；初次关闭记忆的会话保存空快照。
上下文估算保留 provider 实测 usage 锚点，只估算新增消息并补快照与工具开销的差值，
这些开销随锚点保存和恢复；没有 usage 时才进行全量字符估算。
固定指导语与记忆正文一起加入 system prompt，条目采用带 scope 和 id 的文本格式。
当前用户指令优先，记忆不构成执行授权。

检索采用本地词项匹配，支持中日韩文字，无向量/语义模型。每次最多约 2048 个估算 token，
同时受窗口的 1/16 和当前剩余上下文限制，宿主预留窗口的 20% 供后续生成。
返回预算包含整个 JSON 结果，完整条目逐个进入，不截断正文；`totalMatches` 表示全部命中数，
`truncated` 表示部分命中未返回。空间不足以读取时返回 `notRun: true` 和
`reason: insufficient_context`，需先压缩已完成历史。没有查询次数限制、证据资格或旧结果回放；
重复检索会读取当前存储。token 数使用仓库现有估算，并非精确 tokenizer。

记忆保存简短偏好、明确纠正和确认过的事实；长报告放在项目文件中，条目记录结论和文件位置。
不保存猜测、临时进度、原始转储、秘密或已有 Skill/字典维护的知识。
所有记忆都是历史资料，当前用户指令优先，记忆不构成执行授权。
专用校对/探索子 Agent 不直接获得记忆工具。

## 本地数据

翻译项目数据位于用户数据目录的 `mnemon/<项目绝对路径的哈希>/mnemon.sqlite3`，
翻译全局数据位于 `mnemon/global/mnemon.sqlite3`。翻译沿用旧路径，原先的共享记忆归属翻译 Agent。
提取项目数据位于 `mnemon/extraction/<游戏绝对路径的哈希>/mnemon.sqlite3`，
提取全局数据位于 `mnemon/extraction/global/mnemon.sqlite3`，首次使用为空，不读取翻译的旧记忆。
默认用户数据目录为 `~/.galtransl`，支持既有 `GALTRANSL_DATA_DIR` 覆盖。
翻译按翻译项目目录隔离，提取按游戏目录隔离，因此同一游戏的不同提取工作区可以复用记忆。
同类 Agent 的不同项目只共享该类型的 global 条目；路径移动会使用新项目范围，该类型的全局记忆继续可用。
同一路径用于翻译和提取时，两类 Agent 的项目记忆仍相互隔离。已有会话保留历史快照，新会话按新范围构建快照。

各 SQLite 库采用同一精简结构，各自只包含记忆条目和调用回执两张表，不生成 Markdown。
关闭开关或删除/重置会话保留两层记忆。Agent 配置中的记忆列表可查看完整正文、范围、重要性、id
和更新时间，支持编辑、手动存入和逐条确认删除；关闭记忆插件也能管理。翻译使用当前项目，提取使用当前游戏目录，
没有选择项目时仍可管理全局记忆。删除立即落库，新会话不再包含该条目；已有会话保留原 system 快照。
备份按需复制对应目录。
启用后的全局和项目记忆会随请求发送到当前配置的模型。

本版直接采用精简结构，无旧分层数据兼容或迁移。不提供自定义命名空间、关系图、分支范围、
独立档案管理、外部 Provider、宿主扩展加载器、后台精炼或同步服务。
